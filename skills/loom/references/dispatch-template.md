# 派单模板（六段式）

主管每次委派施工/审查/验收执行/拆票票时按此骨架写 prompt。原则：子 agent 与主管上下文不共享，派单必须自足——它读完后不需要问任何问题就能开工。

## 六段骨架

```text
【角色与任务】你是施工/审查/验收执行/拆票 agent，负责执行一票：<票据文件绝对路径>。
任务来源：<任务文档绝对路径>（相关章节名）。

【必读清单】按序读完再动手：
1. <票据文件>
2. <票据索引/共同约束文件>
3. <任务文档原文>
4. <仓库协作规则，如 AGENTS.md>
5. <本票涉及的技能文件，如 to-tickets / code-review 的 SKILL.md 绝对路径>

【环境情报】已就绪项逐一列出，不要重做：
- 工作树：<绝对路径>（分支 X，基于 Y，依赖已装、构建已过 exit 0）
- 端口偏移：<项目的端口偏移变量>=<N>（并行跑 e2e 时必须设，避免和其他工作树冲突）
- 主目录零接触；工具链版本与已知坑

【施工步骤】顺序化 1..N；红绿对照写明旧代码工作树的位置与基线提交。

【硬边界】不许做的事逐条列：不碰其他测试/不改规格/不动 handoffs/
不推送、不开 PR、不合并（任务文档另有要求除外）；预期现象不许当缺陷修。

【回报格式】作为最终回复（不要写进任务文档——回报由主管统一写回）：
1. 施工内容（含冲突清单/根因结论）
2. 提交（分支名、最新提交哈希）
3. 证据清单（每条：命令、退出码、日志路径/截图路径）
4. 未覆盖项 / 风险
5. 「需要决定」（如有）
另写明：有疑问走双向通道 SendMessage 问主管，禁止直接问用户。
```

## 变体要点

- **拆票票**：加「本步只起草不写盘」；输出范围只含**票据内容与依赖**（编号票据 + Blocked by + 验收标准复选框 + 审查方式「逐票审 / 并入整单」及理由 + 依赖图），执行方、实例数、并行拓扑由主管随后编排，不在拆票输出内（草案中出现此类建议仅作参考）；意图读不懂时列「存疑」节而不是自行解读。写明「主管的意见会用 SendMessage 发回给你，由你修改并写入」——写入不另派新实例。
- **审查票**（逐票）：派给专家。写明起点提交和对照的票据；审查方不改被审代码；两处以上「超范围改动」要单独给出必要性与风险评估。结论只能是通过 / 打回 / 升级。
- **整单审查票**：全部施工收进后派给专家一次。起点是任务开始前的基线提交，对照的是任务文档（不是逐张票），只看整体是否交付了任务文档要的东西、有没有超范围；不重审已通过的逐票细节。列出标为「并入整单」的票：这些票的细节在这次一起审，这次就算它们的首审；要求每条阻塞注明属于哪张票。
- **复审票**：返工后的审查轮，用 SendMessage 发回做首审的同一专家实例。起点用上一轮审过的提交，需求用上一轮的阻塞清单，写明「这是复审，只核对这些阻塞」，并要求每条阻塞标注「上轮没修好 / 修复带出来的 / 本轮新发现」；轮数上限与升级上报规则见 SKILL「审查编排」。
- **返工票**：用 SendMessage 发回原施工实例，附专家的阻塞清单；回报里加一项「这次的改法和上次有什么不同」。
- **验收执行票**：派给没碰过这段代码上下文的执行实例（同模型的新实例可以；不为换模型而换人，不派因质量问题被撤下施工的 agent）。列出要跑的命令、旧代码工作树位置、要截的图；回报只交原始证据（命令、退出码、日志路径、截图路径），不下通过结论，不改代码。
- **接手票**（前一个 agent 意外停止或被换下后）：附移交要点——已完成什么（提交哈希）、在途什么、证据/日志在哪、哪些结论已验证不要再重做；换人时另写试过哪些改法、各自为什么被打回，并说明本票已用掉几轮审查。
- **写回回报**（主管自己做，不派票）：写在哪按任务文档或仓库规矩；不混进任何施工分支。专家结论原样引用。

## 派单自检（发出前过一遍）

- [ ] 子 agent 拿到的是路径+正文，而不是「参考我们刚才讨论的」
- [ ] 技能文件给了绝对路径（子 agent 不继承主管的技能上下文）
- [ ] 端口偏移/代理/已装依赖写清，避免重做基线
- [ ] ≤2 票；与其他在途 agent 的工作树、分支、端口无交集
- [ ] 「禁止直接问用户」写进去了
